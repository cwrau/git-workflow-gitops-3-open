# Lab 1.1 - Übung: Versionskontrolle einordnen

Diese Übung verändert kein Repository; sie erzeugt eine schriftliche Einordnung mit Begründung. Die Kodschul Team Site wird erst in Lab 1.2 angelegt.

## Ausgangslage

Vier Situationen aus einem fiktiven kleinen Team, das bisher ohne Versionskontrolle arbeitet:

1. Eine Kollegin verschickt `teamsite_final_v3_wirklich_final.zip` per E-Mail an zwei weitere Personen.
2. Ein Fehler, der vor drei Wochen in `styles.css` behoben wurde, muss zurückgenommen werden, weil er ein anderes Problem verursacht hat - aber niemand weiß mehr genau, welche Zeilen damals geändert wurden.
3. Ein externer Prüfer fragt, wer wann welche Konfigurationsdatei geändert hat und warum.
4. Zwei Personen bearbeiten gleichzeitig dieselbe Datei auf einem gemeinsamen Netzlaufwerk; die zuletzt gespeicherte Version überschreibt die andere vollständig.

## Aufgaben

1. Jede Situation einem der vier Grundprinzipien zuordnen: Rückgängigmachen, Audit-Trail, Reproduzierbarkeit oder Zusammenarbeit ohne Überschreiben.
2. Für jede Situation in 1-2 Sätzen begründen, welches konkrete Git-Konzept (z. B. Commit, Commit-Nachricht, Historie, Branch) das Problem lösen würde.
3. Eine kurze Tabelle mit den Spalten "Situation", "Prinzip", "Lösungsidee mit Git" erstellen.

## Beobachtbares Ergebnis

Eine ausgefüllte Tabelle mit vier Zeilen, in der jede Situation ein Prinzip und eine konkrete Git-bezogene Lösungsidee zugeordnet bekommen hat.

## Abschlusskriterien

- Alle vier Situationen sind einem Prinzip zugeordnet.
- Jede Zeile nennt ein konkretes Git-Konzept, kein allgemeines "Git hilft dabei".
- Keine zwei Situationen teilen sich dieselbe Begründung wortgleich.

## Erweiterung (optional)

Eine fünfte, selbst erfundene Situation aus der eigenen beruflichen Praxis ergänzen und ebenfalls einordnen.
